Live satellite viewer

Everything you read about in the series, made literal. This globe pulls live orbital elements from CelesTrak and propagates each satellite in your browser with the SGP4 model — the same math used by mission controllers — to place thousands of objects in real time.

How this works

  • Data: two-line element sets (TLEs) fetched live from CelesTrak. If the request is blocked or offline, a small bundled snapshot is used so something always renders.
  • Propagation: satellite.js runs SGP4 entirely client-side to turn each TLE into an Earth-centred inertial position for the current (simulated) time.
  • Rendering: Three.js draws the Earth (NASA Blue Marble) inside a NASA deep-star-map sky, with the globe spinning at sidereal rate beneath the orbits.
  • View modes: True scale places every satellite at its real altitude, so the dense low-Earth-orbit shells crowd against the globe while distant GEO objects sit far out. Shell view applies a compressed, log-style radial scale — a visualization aid, not a physical one — that stretches those low altitudes so the orbital shells fan out into visible bands. Both come from the same data; only the altitude-to-distance mapping changes.
  • Controls: the ☰ menu over the canvas switches view mode, toggles layers (satellites, orbit trace, starfield, Earth) on or off, and resets the camera.
  • Colour coding: every dot is tinted by category — Starlink, OneWeb, space stations, navigation (GPS/GLONASS/Galileo/BeiDou), Iridium, and a catch-all "other" — so the shells you see in Shell view are easy to tell apart. The colour key under the controls lists only the categories present in the currently loaded group, with live counts.
  • Hosting: it is all static and runs on GitHub Pages — no server, no build-time data.

Geographic registration is approximate; this is a visualization, not a tracking tool. For precise pass predictions you would also model observer location, light-time, and atmospheric refraction.
