Asyncio

How Python's event loop turns blocking I/O into cooperative concurrency.

#python #asyncio #concurrency

asyncio provides single-threaded concurrency through an event loop that multiplexes many I/O-bound tasks. Instead of blocking a thread while waiting on the network, a coroutine awaits and yields control back to the loop, which runs other ready tasks in the meantime.

Coroutines and the event loop

A coroutine is defined with async def and only makes progress when driven by the loop:

import asyncio

async def fetch(name: str, delay: float) -> str:
    await asyncio.sleep(delay)  # yields to the loop instead of blocking
    return f"{name} done"

async def main() -> None:
    results = await asyncio.gather(
        fetch("a", 1.0),
        fetch("b", 0.5),
    )
    print(results)

asyncio.run(main())

Why it scales

With blocking I/O, serving N concurrent connections costs roughly N threads. With an event loop the cost is dominated by memory per task, not per thread, so a single process can keep many thousands of sockets in flight. If each task spends a fraction ppp of its time actually using the CPU, the loop can in principle interleave about

N≈1pN \approx \frac{1}{p}N≈p1​

tasks before the CPU saturates — which is why asyncio shines for I/O-bound workloads and does little for CPU-bound ones.
