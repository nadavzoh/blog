Caching

Cache strategies, invalidation and the math behind hit ratios.

#system-design #caching #performance

A cache stores the results of expensive work close to where it is needed so repeated requests are served cheaply. The hard parts are placement, eviction and invalidation.

Effective latency

If a cache serves a fraction hhh of requests (the hit ratio) at latency thitt_\text{hit}thit​ and the rest fall through to the origin at tmisst_\text{miss}tmiss​, the average latency is:

tavg=h⋅thit+(1−h)⋅tmisst_\text{avg} = h \cdot t_\text{hit} + (1 - h) \cdot t_\text{miss}tavg​=h⋅thit​+(1−h)⋅tmiss​

Invalidation

There are only two hard things in computer science: cache invalidation and naming things.

Common strategies include time-to-live (TTL) expiry, write-through caches that update on every write, and cache-aside, where the application loads and populates the cache on a miss.
